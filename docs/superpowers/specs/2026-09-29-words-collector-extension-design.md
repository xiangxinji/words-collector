# Words Collector Chrome 扩展设计

日期：2026-09-29

## 目标与成功标准

初始化一个无需构建步骤即可加载的 Chrome Manifest V3 扩展。在扩展弹窗里开启收集后，用户在普通 HTTP/HTTPS 网页双击选中文字，所选文字将保存到本机的扩展存储。关闭开关后，后续双击不再保存。重新打开弹窗和网页后，开关状态与已收集的文字依然存在。

## 首版范围

- 提供一个弹窗，仅显示收集开关及必要的状态/错误提示；不展示或管理词表。
- 捕获网页正文中的双击选区。去除选中文字首尾空白；空选区不保存；包含空格的选区整体保存，不进行分词。
- 首次使用默认关闭。收集相同文字（完全一致、区分大小写）时只保留一份。
- 数据仅保存在 `chrome.storage.local`，不发送网络请求、不云端同步。
- 不支持 Chrome 内部页面、其他扩展页面、非 HTTP/HTTPS 页面或输入控件内部选区。

## 实现结构与数据流

- 根目录 `manifest.json`：声明 Manifest V3、`storage` 权限、HTTP/HTTPS 页面上的静态内容脚本和弹窗；不请求其他权限。
- 弹窗（`popup.html`、`popup.js`，按需少量 CSS）：初始化时读取 `collectionEnabled`，缺失视为 `false`。用户切换时写入该布尔值；写入失败时恢复之前的界面状态并显示错误，不让弹窗误报已开启。
- 内容脚本（`content.js`）：监听页面 `dblclick`；忽略发生在输入框或可编辑区域内的双击；其他事件每次读取 `collectionEnabled`，仅在开启时读取 `window.getSelection()` 的文本并 `trim()`。非空时调用 `chrome.storage.local.set({ ["word:" + text]: text })`（例如 `word:hello`）。再次收集完全相同的文字会覆盖同一键，而不是添加重复项；不同页面同时保存不同文字也不会竞争一个共享列表。脚本不干预网站的默认双击行为。
- 切换开关影响切换完成后发生的新双击事件；已开始执行的事件不保证被取消。内容脚本读写异常不应阻止网页操作，也不显示含选中文字的错误日志。

## 验证

- 使用 Node 自带测试能力模拟浏览器 API 与双击事件，覆盖默认关闭、切换及其持久化、空白选区、正常保存、重复保存、关闭后不保存，以及存储失败时弹窗状态回退。
- 以 `README.md` 记录在 `chrome://extensions` 中开启开发者模式、加载未打包扩展、在普通网页中切换开关并双击选中文字的手动验证流程；说明如何通过扩展开发者工具检查本地存储。
- 检查清单文件合法性；运行自动化测试；在可用的 Chrome 环境下手动验证实际双击行为。

## 不在首版范围

词表展示、删除、导出、跨设备同步、自动分词、大小写归一化、快捷键、右键菜单、动态注入、构建框架或后端服务。
